# Developer API

The developer API gives companies and AI agents programmatic control over their streams.
It covers two use cases: **company-initiated verification** (your backend calls the agent)
and **autonomous operation** (GitHub pushes events to the agent directly).

**Base URL:** `https://api.cronstream.xyz`

## Authentication

| Method | How | Who |
|---|---|---|
| **API key** | `Authorization: Bearer cs_live_<key>` | Registered companies. Generated once in Settings › Developer. Shown once, cannot be retrieved. |
| **x402** | `X-PAYMENT: <payment-proof>` | AI agents and scripts without a registered account. Pay per call in USDC on Base. |

Requests without a valid key or payment return `401 Unauthorized`.
Requests missing payment credentials on x402-gated endpoints return `402 Payment Required`
with full payment instructions in the response body.

## Company endpoints

### POST /api/v1/verify-milestone `API key | x402`

Run milestone verification against the registered source and return a signed EIP-712 extension voucher.
Your backend then submits the voucher on-chain to extend the stream window. x402 price: $0.10 per call.

**Request body**

```json
{
  "streamId":           "0x...",
  "contractorAddress":  "0x...",
  "nonce":              3,
  "verificationSource": "github",
  "verificationTarget": "owner/repo",
  "githubPayload":      { },
  "extensionDurationSeconds": 604800
}
```

| Field | Required | Description |
|---|---|---|
| `streamId` | Yes | 0x-prefixed bytes32 stream ID |
| `contractorAddress` | Yes | Contractor wallet address |
| `nonce` | Yes | Current on-chain nonce (integer). Read from the contract before calling. |
| `verificationSource` | No | `github` \| `jira` \| `bitbucket` \| `figma`. Defaults to the stream's registered source. |
| `verificationTarget` | No | Repo path, ticket key, or URL. Defaults to the stream's registered value. |
| `githubPayload` | Required for GitHub | Raw GitHub webhook event body. Must be a merged PR with passing CI. |
| `extensionDurationSeconds` | No | Period length in seconds. Standard B2B periods: 1 week (604800), 2 weeks (1209600), or 1 month (2592000). Minimum 1 week. Defaults to the stream's registered period. |

**Success response**

```json
{
  "success": true,
  "verification": {
    "source":    "github",
    "target":    "owner/repo",
    "prNumber":  42,
    "mergedAt":  "2026-05-27T18:00:00Z",
    "ciPassed":  true
  },
  "voucher": {
    "streamId":                 "0x...",
    "extensionDurationSeconds": 604800,
    "nonce":                    3,
    "expiry":                   1748100000,
    "signature":                "0x..."
  }
}
```

Pass the full `voucher` object to `extendStream()` on the contract.
The signature is over `ExtensionVoucher(streamId, extensionDurationSeconds, nonce, expiry)`.

**Failure response**

```json
{ "success": false, "error": "No qualifying PR found in the last 7 days", "failedLayer": "github" }
```

### POST /api/v1/register-stream `API key | x402`

Register a stream with the agent after the `createStream` transaction confirms on-chain.
This tells the agent which source to watch and starts autonomous monitoring. x402 price: $0.05 per call.

**Request body**

```json
{
  "streamId":                 "0x...",
  "verificationSource":       "github",
  "verificationTarget":       "owner/repo",
  "recipient":                "0x...",
  "token":                    "0x...",
  "ratePerSecond":            "1157407407407",
  "extensionDurationSeconds": 604800,
  "chainId":                  421614
}
```

**All fields are required.** A stream registered with missing fields cannot be verified,
so the agent rejects the request with `400 Missing required fields`.
Register only after the `createStream` transaction confirms, using values from the `StreamCreated` event.

| Field | Required | Description |
|---|---|---|
| `streamId` | Yes | 0x-prefixed bytes32 stream ID from the `StreamCreated` event |
| `verificationSource` | Yes | `github` \| `jira` \| `bitbucket` \| `figma` |
| `verificationTarget` | Yes | Repo path (`owner/repo`), Jira project key, Bitbucket workspace/repo, or Figma file URL |
| `recipient` | Yes | Contractor wallet address |
| `token` | Yes | ERC-20 token address being streamed |
| `ratePerSecond` | Yes | Token units per second as a string (from the `StreamCreated` event) |
| `extensionDurationSeconds` | Yes | Period length in seconds. Standard B2B periods: 1 week (604800), 2 weeks (1209600), or 1 month (2592000), minimum 1 week. |
| `chainId` | Yes | Chain the stream is on (421614 Arbitrum Sepolia, 46630 Robinhood). |

**Response**

```json
{ "success": true, "streamId": "0x...", "verificationSource": "github", "verificationTarget": "owner/repo" }
```

### GET /api/v1/streams/pending `API key`

Returns all streams for an address that are expired on-chain and have unreclaimed funds or unpaid contractor balances.

**Query parameters**

| Param | Required | Description |
|---|---|---|
| `address` | Yes | Company or contractor wallet address |

```bash
curl "https://api.cronstream.xyz/api/v1/streams/pending?address=0xWALLET" \
  -H "Authorization: Bearer cs_live_<key>"
```

**Response**

```json
{
  "address": "0x...",
  "pending": [
    {
      "streamId":         "0x...",
      "chainId":          421614,
      "streamValidUntil": "1747000000",
      "reclaimable":      "1875000000",
      "contractorOwed":   "125000000",
      "token":            "0x...",
      "recipient":        "0x..."
    }
  ]
}
```

### DELETE /api/v1/stream/:streamId `API key`

Remove a stream from the agent registry and stop monitoring it. Only the stream sender can call this. Does not affect on-chain state.

```bash
curl -X DELETE https://api.cronstream.xyz/api/v1/stream/0xSTREAM_ID \
  -H "Authorization: Bearer cs_live_<key>"
```

```json
{ "success": true, "streamId": "0x...", "message": "Stream removed from agent registry" }
```

Returns `403` if the caller is not the stream sender.

## Connecting GitHub (autonomous mode)

CronStream connects to GitHub as a **GitHub App**, the same way Render or Vercel do —
not a manual per-repo webhook. Whoever owns the verification repo installs the app on it from
**Settings › Integrations › Connect GitHub**. Once installed, GitHub delivers
events for every granted repo to the agent automatically. There is no webhook URL, secret, or
payload configuration to set up by hand.

| Who owns the repo | Who installs the app |
|---|---|
| Company-owned repo | The company installs it; the contractor works as a collaborator. Their pushes fire events because the app is on the repo. |
| Contractor-owned repo | The contractor (repo admin) installs it. The agent resolves the installation by repo, so verification works regardless of which account installed. |

No commit-message metadata is required. The agent maps each repo to its installation and looks up
the registered stream by repo automatically. The legacy `CronStream-Stream-Id` /
`CronStream-Nonce` commit tags are still parsed if present, but are no longer needed.

### Continuous-delivery verification

Payment is tied to delivery, not the calendar. The stream starts locked and begins flowing the
moment work is first verified, then keeps flowing as long as the contractor keeps shipping.
If delivery stops, the window decays and the stream freezes within one period. Concretely:

- The GitHub App webhook drives it. On a merged PR or a push to the default branch, the agent
  looks up the stream(s) registered to that repo and verifies the work (merged PRs *and*
  direct commits, with passing CI) since the last window.
- When a stream is **pending** (locked) and qualifying work is found, the agent opens
  a window immediately — no waiting a full period first.
- When an active stream is within 48h of expiring and new work exists, the agent tops it up by one
  period, so a delivering contractor never actually freezes — the balance streams continuously. A
  stream with healthy runway is left untouched, so frequent merges never stack runaway windows.
- Each extension signs the EIP-712 voucher and submits `extendStreamWindowWithSignature()`
  on-chain. If no qualifying work is found, the stream freezes and the company can reclaim.

### POST /api/v1/webhook/github `HMAC`

Receives GitHub App events (push, pull_request, workflow_run, installation). HMAC-verified against `GITHUB_WEBHOOK_SECRET`. Installation events map repos to their app installation; a merged PR or default-branch push triggers verification for every stream registered to that repo and extends it if qualifying work is found.

<Callout type="info">
  This endpoint is managed by the GitHub App — you don't call or configure it directly.
  Installing the app from the dashboard wires it up automatically.
</Callout>

## Open endpoints

These require no authentication and are available to any client.

### GET /api/v1/streams

All streams for a wallet address, enriched with live on-chain data.

```bash
curl "https://api.cronstream.xyz/api/v1/streams?address=0xWALLET"
```

```json
{
  "address": "0x...",
  "streams": [
    {
      "stream_id":        "0x...",
      "chain_id":         421614,
      "ratePerSecond":    "1157407407407",
      "streamValidUntil": "1748000000",
      "totalDeposited":   "2000000000",
      "totalWithdrawn":   "500000000",
      "balance":          "125000000",
      "isActive":         true
    }
  ]
}
```

### GET /api/v1/stream/:streamId/balance

Live on-chain withdrawable balance for a stream.

```bash
curl "https://api.cronstream.xyz/api/v1/stream/0xSTREAM_ID/balance"
```

```json
{
  "streamId":         "0x...",
  "chainId":          421614,
  "balance":          "125000000",
  "ratePerSecond":    "1157407407407",
  "streamValidUntil": "1748000000",
  "totalDeposited":   "2000000000",
  "totalWithdrawn":   "500000000",
  "isActive":         true
}
```

### GET /api/v1/stream-status/:streamId

Agent-side metadata for a stream including the full extension history.

```bash
curl "https://api.cronstream.xyz/api/v1/stream-status/0xSTREAM_ID"
```

```json
{
  "streamId":   "0x...",
  "stream":     { },
  "extensions": [
    {
      "stream_id":           "0x...",
      "nonce":               3,
      "extended_until":      "1748000000",
      "verification_source": "github",
      "created_at":          1747900000
    }
  ]
}
```

## Error codes

| Status | Meaning |
|---|---|
| `400` | Invalid stream ID, address, or missing required fields |
| `401` | Missing or invalid API key or JWT |
| `402` | x402 payment required — response body contains payment instructions |
| `403` | Caller is not the stream sender |
| `404` | Stream not found in registry or on-chain |
| `409` | Stream already registered |
| `422` | Milestone verification failed, no qualifying deliverable found |
| `500` | Internal error |
