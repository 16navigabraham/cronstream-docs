# How It Works

Cronstream operates as a Uniswap v4 hook attached to a yield-bearing pool. The protocol runs a five-step lifecycle that begins when the first LP deposits and ends when the keeper broadcasts a distribution transaction.

## The five-step lifecycle

<Steps>

### Liquidity range tracking

When an LP adds a position to a Cronstream-attached pool, the `afterAddLiquidity` hook callback fires. The hook records the LP's wallet address, their liquidity delta, and their current ownership fraction relative to total pool liquidity. This data is written to a persistent on-chain mapping — the hook's liquidity ownership matrix.

When an LP removes or reduces a position, `afterRemoveLiquidity` fires and scales down their recorded share proportionally.

### Surplus accumulation

Yield enters the pool through two channels:

- **Token rebases.** When USDY or USDM rebases, the `PoolManager`'s actual ERC-20 balance increases above its internally tracked reserves. This unaccounted delta is the rebase surplus.
- **Swap fees.** Trading activity generates fee income that accumulates inside the pool's fee growth registers.

The `afterSwap` and `afterDonate` callbacks measure the current pool token balance against the hook's internal ledger on each swap or donation event, tracking the growing surplus in real time.

### Reactive smart contract monitoring

`distributeYield()` is a fully public, permissionless entrypoint — any address can call it. The caller receives exact gas reimbursement from the yield pool inline, making the protocol self-sustaining regardless of who triggers it.

In practice, Cronstream deploys a [Reactive Network](https://reactive.network) smart contract as its primary automation client. Instead of a centralized off-chain script, the Reactive contract monitors the pool's on-chain balance delta autonomously and calls `distributeYield()` the moment the threshold is crossed — with no human intervention and no server required. The callback payload includes an execution flag that determines how gas is settled:

- **Standard mode (flag 0):** The hook runs the inline exact-output ETH swap and reimburses the Reactive relayer from the yield pool.
- **Sponsored mode (flag 1):** If an ecosystem foundation has pre-funded a Reactive relayer treasury or paymaster, the swap is skipped and 100% of yield flows to LPs.

Because the entrypoint has no access control, the Reactive contract is not a dependency — any keeper, bot, or LP can trigger a distribution independently if needed.

### Dollar threshold trigger

When accumulated yield crosses a configurable capital efficiency threshold (default: **$1,000 USDC equivalent**), the keeper broadcasts a transaction calling `distributeYield(PoolKey calldata key)` on the hook contract.

The threshold prevents distributions from being uneconomical — a gas-cost-to-yield ratio below the threshold means the keeper's reimbursement would consume a material fraction of the distributed amount, which is undesirable for LPs. The threshold is tunable at deployment.

### Atomic flash settle and push payout

The distribution executes as a single atomic transaction inside a `poolManager.unlock()` session:

1. The hook pulls the yield surplus from the `PoolManager` using `poolManager.take()`
2. It calculates the exact gas cost of the transaction at runtime using `gasleft()` bookkeeping
3. It executes an inline exact-output swap on a native ETH/stablecoin pool to acquire the exact ETH needed to reimburse the keeper
4. It transfers the ETH directly to `tx.origin` (the keeper wallet)
5. It loops the remaining stablecoin balance and transfers each LP's pro-rata share directly to their wallet via `IERC20.transfer()`
6. All `PoolManager` currency deltas are settled to zero before the unlock session closes

The `PoolManager` validates that `NonzeroDeltaCount == 0` before accepting the state transition. If any delta is unsettled, the entire transaction reverts.

</Steps>

## Distribution flow diagram

```
[ Pool: USDY/USDC ]
       │
       │ rebase / swap fees
       ▼
[ Cronstream Hook ]
       │
       │ distributeYield() triggered by keeper
       ▼
[ poolManager.unlock() → unlockCallback() ]
       │
       ├──► poolManager.take(surplusAmount)
       │
       ├──► inline ETH/USDC swap → reimburse keeper (tx.origin)
       │         └── ~0.2% of surplus consumed
       │
       └──► IERC20.transfer() × N LPs → wallets
                 └── ~99.8% of surplus distributed
```

## LP experience

From the LP's perspective, Cronstream is invisible. They deposit into a Uniswap v4 pool in the normal way. At unpredictable intervals — determined by trading volume and rebase frequency — yield arrives directly in their wallet with no action required. There is no claim transaction, no gas cost to the LP, and no dashboard to check.

<Callout type="info">
  LPs never interact with the Cronstream hook directly. The only user-facing change is that yield appears in their wallet automatically rather than requiring a claim.
</Callout>

## Security model

The hook holds no principal funds at any point. All LP liquidity remains inside the `PoolManager` singleton, which is the canonical Uniswap v4 security boundary. The hook only ever handles yield surplus — the delta between the pool's actual token balance and its internally tracked reserves.

Reentrancy is guarded via an EIP-1153 transient storage lock that is set at `distributeYield()` entry and automatically cleared when the transaction frame closes, with zero permanent storage cost.
