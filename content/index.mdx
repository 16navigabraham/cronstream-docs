# CronStream Protocol

**Milestone-gated token streaming. Funds flow only when work is provably done.**

CronStream is an open-source protocol for B2B payment streaming on EVM chains. A company deposits the full engagement budget upfront — but the stream starts locked. The contractor earns nothing until an autonomous agent verifies a completed deliverable and cryptographically unlocks the next payment window.

If work stops, the agent stops signing. The stream freezes at expiry, and the company reclaims unearned funds. No human intervention. No emergency transaction.

---

## The Problem

Every Web3 streaming protocol today streams money based on time alone. Superfluid and LlamaPay were built for high-trust internal teams — DAO core contributors, token vesting, recurring salaries. In those environments, unconditional streaming is fine.

B2B contracting is different. When a DAO in London hires a developer in Lagos, they need mathematical guarantees, not blind faith. If the contractor goes dark mid-stream, a time-based stream drains the treasury until a human notices. And as regulations tighten — IRS 1099-DA, MiCA — streaming money without a verifiable audit trail of why it moved creates compliance exposure.

CronStream adds a cryptographic circuit breaker: every dollar unlocked is tied to an on-chain event proving work was done.

---

## How It Differs

| | Superfluid / LlamaPay | CronStream |
|---|---|---|
| Payment trigger | Time (unconditional) | Verified deliverable |
| If contractor ghosts | Stream drains until cancelled | Stream freezes at expiry |
| Audit trail | None | Every dollar tied to a signed on-chain event |
| Unearned funds | Manual cancel required | `reclaimUnearned()` — trustless recovery |
| Built for | Internal DAO teams, vesting | Remote contractors, cross-border B2B |

CronStream is fully open source. The contract, agent node, and frontend are all public — no operator dependency. Any protocol or company can deploy their own instance with their own agent signer.
